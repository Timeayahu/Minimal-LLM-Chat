# Nexus Agent Kernel 执行日志

## 文档定位

本文件只回答一个问题：**项目每一次实际执行了什么。**

它不是路线图，也不负责定义愿景、阶段或未来任务。项目愿景、里程碑、当前阶段、
完成标准和后续优先级统一维护在
[`PROJECT_PLAN.md`](PROJECT_PLAN.md)。

## 记录规则

- 每次完成一轮代码、测试、文档或项目治理变更后，新增一条执行记录。
- 按时间倒序记录，最新执行放在最前面。
- 每条记录必须包含：执行目标、解决的问题、实际变更、验证结果。
- 重要设计取舍、遗留风险和范围变化必须明确记录，不能只写“完成优化”。
- 规划中的工作不写入本文件；没有实际交付的讨论只记录到项目计划的决策区。
- 执行编号使用 `EXE-NNN`，永久递增，不复用。

## 标准模板

```markdown
### EXE-NNN｜YYYY-MM-DD｜执行标题

- 关联里程碑：`M?`
- 状态：完成 / 部分完成 / 失败 / 回滚
- 执行目标：
- 解决的问题：
- 实际变更：
- 验证结果：
- 设计取舍或遗留风险：
```

### EXE-029｜2026-07-25｜完成 Agent Kernel 基线验收并关闭 M0

- 关联里程碑：`M0 项目重基线与治理`
- 状态：完成

  - MemoryStore 保持对旧版顶层列表 JSON 的读取兼容，并在下一次写入时迁移到版本化对象格式。
  - 增加重置取消终态、Memory ID 不复用和旧数据迁移的回归测试。

### EXE-024｜2026-07-18｜Agent Trace 持久化与运行边界整理

- 关联里程碑：`M2 Memory 与可观测性`
- 状态：完成
- 执行目标：让一次 Agent Run 可被稳定记录、查询和复盘。
- 解决的问题：旧 Trace 依赖 Session 快照，进程中断会丢失未保存事件，而且 Conversation 与 Runtime Trace 混在一起。
- 实际变更：
  - 建立 `TraceEvent`、`TraceLogger` 和 JSONL TraceStore。
  - 为每次请求增加 `run_id`，持续记录 planner、tool、confirmation、final 和终态事件。
  - 确认后继续复用原 `run_id`，并增加敏感字段脱敏。
  - 移除 Session Trace 双写，JSONL 成为唯一运行观测数据源。
  - 将运行编排拆入 `AgentRuntime`，新增工具 Policy、共享执行器和 `RunRecorder`。
  - 将运行源码收拢到 `nexus/`，按 `cli/agent/context/tools/llm` 组织。
- 验证结果：覆盖即时落盘、查询、脱敏、损坏行、事件顺序、确认续跑和异常终态的测试通过。
- 设计取舍或遗留风险：暂不引入 SQLite、指标聚合和多 Provider 抽象，等待真实查询或入口需求。
